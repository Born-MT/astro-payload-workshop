# Glossary — every word you will meet today

Keep this open during the hands-on. Each word is next to the WordPress word it replaces, where one exists. When there is no WordPress equivalent, the row says so; those are the ones worth reading twice.

The condensed version is in the slides (the "Jargon" slides). This is the full list.

---

## 1. The shape of the project

| Word | What it is | WordPress word |
| --- | --- | --- |
| **Monorepo** | One git repo holding several apps that are developed together. Here: `apps/cms` and `apps/web`. | One repo with the theme and a custom plugin in it |
| **pnpm** | The package manager we use instead of npm. Faster, and it understands workspaces. | Composer, roughly |
| **Workspace** | pnpm's word for "the packages in this monorepo". `pnpm-workspace.yaml` lists them. | — |
| **`pnpm --filter web <cmd>`** | Run a script inside one workspace package. `pnpm dev:cms` and `pnpm dev:web` are shortcuts for this. | — |
| **`apps/cms`** | The Payload app. Owns the database, the admin panel and the API. Runs on port 3300. | wp-admin + the database |
| **`apps/web`** | The Astro app. Owns the public website. Runs on port 4321. Never touches the database. | The theme |
| **Headless CMS** | A CMS that stores and serves content over an API and has no opinion about the website. Payload is one. | Headless WordPress via `/wp-json` |
| **REST API** | URLs that return JSON. `GET /api/services` lists services. Generated by Payload from your collections. | `/wp-json/wp/v2/service` |
| **JSON** | The text format the two apps exchange. If you can read a PHP array, you can read JSON. | The output of `wp_json_encode()` |
| **HTTP status** | The number that comes with every response. 200 ok, 404 not found, 401 not logged in, 500 the server broke. | Same words, `status_header()` |
| **`.env`** | A file of secrets and settings read at boot. Never committed. `PAYLOAD_SECRET`, `DATABASE_URI`, `PAYLOAD_URL`. | `wp-config.php` |
| **Node** | The JavaScript runtime both apps run on. The equivalent of PHP-FPM for this stack. | PHP |
| **ESM / `import`** | JavaScript's module system. `import { x } from './file'` at the top of a file. | `require_once` |
| **TypeScript** | JavaScript with types. A `.ts` file is JavaScript plus a description of the shapes of things. | PHP with strict types and docblocks, checked before the code runs |
| **Type** | A named shape. `Service` is "an object with a title, a slug, a summary…". Generated from the collection. | The shape of `get_fields()`, written down |
| **Typecheck** | `pnpm typecheck`. Reads every file and reports every place a type does not fit. Your fastest test. | No equivalent. This is the thing PHP does in production. |
| **Union type** | `number \| Service` means "either a number or a Service". You must handle both. See *depth*. | — |
| **Type guard** | `typeof s === 'object'` inside an `if`. After it, TypeScript knows which half of the union you have. | `is_object()` |
| **`async` / `await`** | Functions that fetch or read the database are async; `await` pauses until the result is in. | — (PHP is synchronous) |

## 2. Payload: the content model

| Word | What it is | WordPress word |
| --- | --- | --- |
| **Collection** | A content type, defined in one TypeScript file. Gets a database table, an admin screen and an API endpoint. | Custom Post Type + its ACF field group |
| **Global** | A single document, not a list. Site settings, header, footer. `/api/globals/header`. | Options page, `get_option()` |
| **Document** | One row in a collection. One service, one case study. | A post |
| **Field** | One column of a collection. Has a `name`, a `type`, and options. | An ACF field |
| **`slug` (of a collection)** | The collection's identifier: `slug: 'case-studies'`. Sets the table name and the API path. | The post type name in `register_post_type()` |
| **`slug` (as a field)** | A field *you* define on the document, used in URLs. Not automatic; the starter has a hook that fills it from the title. | `post_name` |
| **`useAsTitle`** | Which field the admin list shows as the row title. | `post_title` in the list table |
| **`admin.group`** | The heading a collection sits under in the admin sidebar. Ours are all in "Content". | Menu position |
| **`admin.position: 'sidebar'`** | Puts a field in the right-hand column of the edit screen instead of the main form. | A meta box in the sidebar |
| **`admin.description`** | Help text under a field or collection. | ACF "Instructions" |
| **Access control** | `access: { read, create, update, delete }`. Each is a function returning true/false. `read: () => true` is public. | `capability_type`, `current_user_can()` |
| **Hook** | A function Payload runs at a moment in a document's life. Collection-level or field-level. | `add_action('save_post')`, `add_filter()` |
| **`beforeValidate`** | Runs before the data is validated. Where the slug gets generated. | `sanitize_title()` on save |
| **`beforeChange`** | Runs after validation, before the write. Normalising, computing fields. | `wp_insert_post_data` |
| **`afterChange`** | Runs after the write. Notifications, cache busting, webhooks. | `save_post` |
| **`afterRead`** | Runs on the way out of the database. Reshape what the API returns. | `the_content` filter |
| **`payload.config.ts`** | The root config. Lists collections, globals, the database adapter, the editor, plugins. | `functions.php` + `wp-config.php` |
| **Registering** | Adding the collection to the `collections` array in the config. Until you do, it does not exist. | `add_action('init', 'register_post_type')` |
| **Auth collection** | A collection with `auth: true`. Its documents can log in. Ours is `users`. | `wp_users` |
| **Upload collection** | A collection with `upload: true`. Its documents are files. Ours is `media`. | The Media Library |
| **Admin panel** | `/admin`. Generated from the config; there is no screen to build. It is a Next.js app that Payload ships. | wp-admin |
| **Local API** | Calling Payload from inside the CMS process: `payload.find({ collection })`. Used in the seed. No HTTP. | `get_posts()` inside a plugin |

## 3. Payload: field types and options

| Word | What it is | WordPress word |
| --- | --- | --- |
| **`text`** | Single line. | ACF Text |
| **`textarea`** | Multi-line plain text. | ACF Textarea |
| **`number`** | A number. `min`, `max` available. | ACF Number |
| **`select`** | One (or `hasMany`) of a list of `options`. | ACF Select |
| **`checkbox`** | Boolean. | ACF True/False |
| **`date`** | A date or datetime. Stored as ISO string. | ACF Date Picker |
| **`email`** | Text validated as an email. | ACF Email |
| **`array`** | A repeatable group of sub-fields. `fields: [...]` nested inside. `minRows`, `maxRows`. | ACF Repeater |
| **`group`** | Sub-fields under one name, not repeatable. `seo: { title, description }`. | ACF Group |
| **`relationship`** | A link to documents in another collection. `relationTo: 'services'`, `hasMany: true`. | ACF Post Object / Relationship |
| **`upload`** | A link to a document in an upload collection. `relationTo: 'media'`. | ACF Image / File |
| **`richText`** | Formatted content. Edited with Lexical, stored as JSON, rendered with `convertLexicalToHTML`. | ACF WYSIWYG / `the_content` |
| **`blocks`** | A list where each item is one of several named shapes. Each shape is a `block` with its own fields. | Gutenberg blocks / ACF Flexible Content |
| **`tabs`, `row`, `collapsible`** | Layout-only fields. They arrange the edit screen and store nothing themselves. | ACF Tab / Accordion |
| **`json`** | Free-form JSON. Rare. | A serialised meta value |
| **`required`** | Cannot be saved empty. | ACF "Required" |
| **`unique`** | No two documents may share the value. Use on `slug`. | — (you would write the check) |
| **`defaultValue`** | Pre-filled on new documents. | ACF "Default Value" |
| **`maxLength` / `minLength`** | Text length limits. | ACF "Character Limit" |
| **`index: true`** | Adds a database index. Use on fields you filter by. | — |
| **`hidden`** | Stored, but not shown in the admin. | — |
| **Lexical** | The rich text editor Payload uses (from Meta). Its output is a JSON tree, not HTML. | TinyMCE, and its output *is* HTML |
| **`convertLexicalToHTML`** | The function that turns a Lexical JSON tree into an HTML string for Astro to render. | `apply_filters('the_content')` |

## 4. Payload: the API and the data

| Word | What it is | WordPress word |
| --- | --- | --- |
| **`GET /api/<slug>`** | List documents. Paginated. | `/wp-json/wp/v2/<type>` |
| **`GET /api/<slug>/<id>`** | One document by id. | `/wp-json/wp/v2/<type>/<id>` |
| **`where`** | The filter. `?where[slug][equals]=x`. Nested keys because filters nest. | `meta_query` / `WP_Query` args |
| **Operators** | `equals`, `not_equals`, `contains`, `in`, `not_in`, `like`, `exists`, `greater_than`, `less_than`, and `_equal` variants. | `compare` in `meta_query` |
| **`sort`** | `?sort=order`. Prefix with `-` for descending: `-completedOn`. | `orderby` + `order` |
| **`limit` / `page`** | Page size (default 10) and page number. | `posts_per_page` / `paged` |
| **Paginated response** | Lists come back as `{ docs, totalDocs, page, totalPages, hasNextPage, ... }`. Your data is in `docs`. | `WP_Query->posts` + `found_posts` |
| **`depth`** | How many levels of relationships to populate. `depth=0` gives ids; `depth=1` gives the related documents inline. Default in REST is 2. | **No equivalent.** In WP you get ids and call `get_post()` yourself. |
| **Populated** | A relationship that came back as a document, not an id. Depends on `depth`. | — |
| **`number \| Service`** | The type of a relationship field, because it may be either. Guard with `typeof s === 'object'`. | — |
| **`pnpm generate:types`** | Reads the config and writes `payload-types.ts`. Run after every field change. | — |
| **`payload-types.ts`** | Generated. One TypeScript type per collection, plus a `Config` type. The frontend imports from it as `@cms/payload-types`. | — |
| **Database adapter** | The package that talks to a database. We use `@payloadcms/db-sqlite`. Postgres and Mongo are the others. | `wpdb`, but swappable |
| **Drizzle** | The query builder under the SQLite and Postgres adapters. You will see it in stack traces. | — |
| **SQLite** | A database in a single file, `apps/cms/payload.db`. Fine for the workshop. Real projects use Postgres. | The MySQL database |
| **`push: true`** | Dev-only. Payload changes the database schema to match your collections on boot. No migrations. | — (WP has no schema for meta) |
| **Migration** | A file describing a schema change, applied in order. What real projects use instead of `push`. Not today. | `dbDelta()`, very loosely |
| **Seed** | A script that creates starter documents. `pnpm seed` runs `seed.ts` through `payload run`. Idempotent: run it twice, still three. | WP-CLI import, or a fixtures plugin |
| **`payload run`** | Runs a TypeScript file with Payload booted. Exits when the module finishes evaluating, so use top-level `await`. | `wp eval-file` |
| **Versions / drafts** | `versions: { drafts: true }` on a collection adds a `_status` of `draft` or `published`, and a history. | Post status + revisions |
| **`imageSizes`** | On an upload collection: the resized variants Payload generates with `sharp`. `card`, `hero`. | `add_image_size()` |
| **`sharp`** | The image processing library. Native, which is why `pnpm` asks to build it. | GD / ImageMagick |
| **Plugin** | A package added to `plugins: []` in the config. `@payloadcms/plugin-seo` adds Yoast-style fields. | A plugin, but only for the CMS side |
| **`PAYLOAD_SECRET`** | Random string used to sign sessions and tokens. In `.env`. | `AUTH_KEY` and friends |
| **`serverURL`** | The CMS's own public URL. Used to build absolute media URLs. | `WP_HOME` / `WP_SITEURL` |
| **CORS / CSRF** | Lists of frontend origins the API will accept requests from. The starter allows `localhost:4321`. | — |
| **Next.js** | The framework Payload's admin panel runs on. You will see it in the CMS logs. You do not write any of it. | — |
| **Turbopack** | Next.js's bundler. The reason `next.config.ts` has a `root` setting. | — |
| **`importMap.js`** | A generated file in `app/(payload)/admin/`. Payload regenerates it; do not edit it. | — |
| **GraphQL** | A second API Payload generates at `/api/graphql`. We do not use it today. | WPGraphQL |

## 5. Astro: the component file

| Word | What it is | WordPress word |
| --- | --- | --- |
| **`.astro` file** | A component. Server-side code at the top, HTML template below. Both pages and components are `.astro` files. | A `.php` template file |
| **Frontmatter** | The code between the two `---` fences at the top. Runs on the server, never in the browser. Imports, fetches, variables. | The PHP at the top of the template |
| **Template** | Everything below the second `---`. HTML with `{expressions}`. | The HTML part of the template |
| **Expression** | `{service.title}`. JavaScript inside the template. `{items.map(...)}` is the loop. | `<?= $x ?>`, `foreach` |
| **Component** | A `.astro` file in `src/components/`, used as a tag: `<ServiceCard service={s} />`. | `get_template_part()` |
| **Props** | The values passed into a component. Read them with `Astro.props`. Declare their types with `interface Props`. | The `$args` of `get_template_part()` |
| **`Astro`** | The global object available in every `.astro` file. `Astro.props`, `Astro.params`, `Astro.url`, `Astro.request`. | `$wp_query`, `$post`, `get_query_var()` |
| **Layout** | A component that wraps a whole page. `<Base title="…">` in `src/layouts/`. | `get_header()` + `get_footer()` |
| **Slot** | Where a layout or component puts its children. `<slot />`. Named slots: `<slot name="head" />`. | `wp_head()`, `wp_footer()`, roughly |
| **Scoped `<style>`** | A `<style>` block in a component applies only to that component's HTML. | — |
| **`set:html`** | `<div set:html={html} />`. Renders a string as HTML. Use for rich text. Trust the source. | `echo` without escaping |
| **`is:inline`** | Tells Astro to leave a `<script>` or `<style>` exactly as written. | — |
| **`class:list`** | `class:list={['card', { active }]}`. Conditional classes. | `post_class()`, roughly |
| **`@/` alias** | Shorthand for `src/` in imports. `@/lib/payload`. Set in `tsconfig.json`. | `get_template_directory()` |
| **`@cms/payload-types`** | Alias pointing into the CMS app's generated types. The typed pipe between the two apps. | — |

## 6. Astro: routing and rendering

| Word | What it is | WordPress word |
| --- | --- | --- |
| **Page** | A `.astro` file inside `src/pages/`. Its path is its URL. | A template in the hierarchy |
| **File-based routing** | `pages/services/index.astro` is `/services/`. No rewrite rules, no hierarchy to resolve. | Template hierarchy + rewrite rules |
| **Dynamic route** | `[slug].astro`. The brackets mark a URL segment that varies. | `single-*.php` |
| **`Astro.params`** | The values of the dynamic segments. `Astro.params.slug`. | `get_query_var('name')` |
| **Rest route** | `[...path].astro`. Matches any depth. | Catch-all rewrite |
| **`Astro.url`** | The full URL of the current request. | `$_SERVER['REQUEST_URI']` |
| **`Astro.request`** | The raw request: headers, method, body. | `$_SERVER`, `$_POST` |
| **`Response`** | Return one from the frontmatter to control status: `new Response(null, { status: 404 })`. | `status_header(404)` |
| **`Astro.redirect()`** | Return it to redirect. | `wp_redirect()` |
| **Endpoint** | A `.ts` file in `pages/` that exports `GET` or `POST` and returns a `Response`. An API route in the web app. | `admin-ajax.php`, a REST route |
| **Middleware** | `src/middleware.ts`. Runs before every request. Auth, redirects, headers. | `init` / `template_redirect` hooks |
| **SSR** | Server-side rendering. The page is rendered per request. Content changes show on refresh. Our setting. | How WordPress always works |
| **SSG** | Static site generation. Every page rendered once at build time to HTML files. Fastest, needs a rebuild on content change. | A full-page cache plugin, done properly |
| **`output`** | `'server'` or `'static'` in `astro.config.mjs`. Picks SSR or SSG for the whole site. | — |
| **`prerender`** | `export const prerender = true` in one page. Makes that page static inside an SSR site. | — |
| **`getStaticPaths()`** | In SSG, the function that lists every URL a dynamic route should build. Not needed in SSR. | — |
| **Adapter** | The package that lets a server-rendered Astro site run somewhere: Node, Vercel, Cloudflare. | The hosting-specific bit of a WP deploy |
| **`astro dev`** | The dev server, with hot reload. Astro 7 runs it as a background daemon when it detects an AI agent: `astro dev logs`, `astro dev stop`. | `wp server`, or Local |
| **`astro build` / `astro preview`** | Build for production; serve the build locally. | — |
| **`astro check`** | The typechecker for `.astro` files. `pnpm typecheck` runs it. | — |
| **Vite** | The build tool under Astro. Where "HMR" and most config errors come from. | — |
| **HMR** | Hot module replacement. Save the file, the browser updates without a full reload. | — |

## 7. Astro: the browser side

| Word | What it is | WordPress word |
| --- | --- | --- |
| **Zero JS by default** | Astro ships no JavaScript to the browser unless you ask. A page of `.astro` components is plain HTML. | The opposite of most themes |
| **Island** | One interactive component on an otherwise static page. Written in React, Svelte, Vue, or plain `<script>`. | A block with its own JS |
| **Hydration** | Loading the JavaScript that makes an island interactive. Controlled per island. | `wp_enqueue_script()`, roughly |
| **`client:load` / `client:idle` / `client:visible`** | Directives on an island that say *when* to hydrate: immediately, when the browser is idle, when it scrolls into view. | — |
| **`client:only`** | Skip server rendering for this component entirely. | — |
| **Integration** | An official add-on: `@astrojs/react`, `@astrojs/sitemap`, `@astrojs/node`. Added in `astro.config.mjs`. | A plugin, for the frontend |
| **`<script>` in a component** | Plain client-side JS. Astro bundles and dedupes it. | `wp_enqueue_script()` |
| **`astro:assets` / `<Image>`** | Astro's image component. Resizes and optimises at build or request time. | `wp_get_attachment_image()` |
| **`import.meta.env`** | Environment variables in Astro. Only ones prefixed `PUBLIC_` reach the browser. | `getenv()`, constants in `wp-config.php` |
| **Content collections** | **Name clash.** Astro has its own "collections" for local Markdown and data files, in `src/content.config.ts`. We do not use them. When a doc or Claude says "collection", check which one. | — |
| **View transitions** | Animated page-to-page navigation, opt-in. Not today. | — |

## 8. Claude Code words used today

| Word | What it is |
| --- | --- |
| **Plan mode** | `Shift+Tab`. Claude proposes a plan and touches nothing until you approve it. |
| **`CLAUDE.md`** | The file Claude reads at the start of every session. Layout, commands, conventions. |
| **Skill / slash command** | A reusable prompt in `.claude/skills/`. `/payload-new-collection` is one. |
| **Hook** | A script that runs before or after a Claude action. Ours block edits to `.env` and dangerous shell commands. Different thing from a Payload hook. |
| **Agent / subagent** | A separate Claude session Claude spawns for a sub-task, with its own context. `code-reviewer` is one. |
| **Context** | Everything Claude currently has in view. Long sessions fill it; `/clear` empties it. |
| **Diff** | The change Claude proposes. You read it before it is applied. The whole point of today. |
| **Permission** | Claude asks before running commands or editing files outside what you have allowed. Do not blanket-allow. |
