# Facilitator guide

**Session:** 25 September 2026 · 1h30 · 30 min presentation + 60 min hands-on.
**Audience:** junior devs, mostly WordPress. Everyone has a Claude Code Teams seat. **Format:** everyone works solo on their own laptop.
**Goal:** every attendee leaves with their own portfolio on Payload + Astro, green through step 5 of the ladder in [TASK_BRIEF.md](TASK_BRIEF.md).
**Solution:** `git checkout solution` — steps 1 to 5 and every stretch card implemented, one commit per step, each tagged, so you can `git log --oneline` it during the debrief.

## The ladder and the gate, in one paragraph

The hands-on is seven steps (0 to 6) with acceptance criteria. `pnpm verify N` runs the criteria for steps 0..N against the attendee's running servers and git log, in order, and stops at the first ✘. A commit tagged `(step N)` or `(card X)` is refused by both the Claude Code hook (`.claude/hooks/step-gate.sh`) and the git `commit-msg` hook until that step is green. `pnpm verify --status` prints where someone is without running anything. You never have to judge whether a step is done; you read the status.

**Walk-around check.** Do not read screens. On any laptop, run:

```bash
pnpm verify --status
```

It prints ✔/✘ per step with a timestamp, and the cards committed. That is the whole conversation starter: "you are on step 3, what is red?"

**When someone is red.** Run `pnpm verify --status`, then `pnpm verify N` for the step they are on. The ✘ line names the acceptance criterion and the `→` line under it says what to look at. Read it out loud with them. Ninety percent of the time it is one of the failure modes below. If it is not, ask them to paste the ✘ line to Claude Code as the prompt, in plan mode.

## Demo prompts that work

Use these on the projector, verbatim, so people see prompt shape rather than magic.

**Step 1, in plan mode:**
```
Create a Payload collection `projects` in apps/cms/src/collections/Projects.ts,
following the conventions in CLAUDE.md and the pattern in Services.ts.
Fields: title (text, required), slug (text, required, unique, sidebar, auto from title),
client (text, required), role (text, required), summary (textarea, required, max 240),
projectUrl (text, sidebar), repoUrl (text, sidebar), completedOn (date, required, sidebar),
stack (array, min 1 max 8, of name:text), highlights (array, min 1 max 4, of value:text + label:text).
Access: public read, everything else requires a user. Admin group "Content", useAsTitle title.
Register it in payload.config.ts and run pnpm generate:types.
Acceptance: pnpm verify 1 is green.
```

**Step 3, typed props:**
```
Create apps/web/src/pages/projects/index.astro and apps/web/src/components/ProjectCard.astro,
mirroring index.astro + ServiceCard.astro. Fetch with getDocs('projects', { sort: '-completedOn', limit: 20 }).
Type the card prop as Project from @cms/payload-types. Card shows client pill, title, summary, role.
Acceptance: pnpm verify 3 is green.
```

**Step 5, the global:**
```
Create a Payload global `profile` in apps/cms/src/globals/Profile.ts from
wordpress-reference/portfolio-plugin/acf-export-profile.json: name (text, required),
headline (text, required, max 80), bio (textarea, required), email (text), location (text),
links (array, max 6, of label:text + url:text). Public read, update needs a user.
Register it under `globals` in payload.config.ts, run pnpm generate:types, seed it in seed.ts
with payload.updateGlobal using my details, then create apps/web/src/pages/about.astro
that fetches it with getGlobal('profile') and renders name, headline, location, email, bio and the links as pills.
Acceptance: pnpm verify 5 is green.
```

**The "ask why" prompt:**
```
Why does the Astro page fetch data in the frontmatter instead of in a <script> tag?
Answer in 3 sentences for someone who knows WordPress.
```

## Failure modes to watch for

| Symptom | Cause | Fix |
| --- | --- | --- |
| Every Bash command Claude runs is blocked | `jq` missing; the kit's safety hook fails closed | `brew install jq`, restart Claude Code. `pnpm doctor` checks it. |
| `pnpm verify` says "CMS is running on :3300 ✘" | `pnpm dev` is not running, or is still booting | Start it in another terminal; wait for both "ready" lines |
| "Collection not found" / `GET /api/projects returned 404` | Not registered in `payload.config.ts` | Add to the `collections` array; restart `pnpm dev:cms` |
| Types in `apps/web` don't know `Project` | Forgot `pnpm generate:types` | Run it; the Astro TS server may need a restart (Cmd+Shift+P → Restart Astro Language Server) |
| `pnpm verify 1`: "Project type is missing: role" | Field left out or misspelled | The list in step 1 of the brief is the contract |
| `pnpm verify 1`: "anonymous create returned 201" | Missing or permissive access rules | Copy the four access rules from Services.ts |
| `pnpm verify 2`: "projects went from 3 to 6" | Seed creates without checking | Find by slug first, create only if missing (the services loop) |
| Admin shows the collection but saving fails with a DB error | SQLite schema out of date | Restart `pnpm dev:cms` (push runs on boot). Nuclear: `pnpm reset` |
| `slug` stays empty | Hook placed on the collection instead of the field | Field-level `hooks.beforeValidate`, see Services.ts |
| `pnpm verify 5`: `GET /api/globals/profile returned 404` | Global not registered | Add to the `globals` array in `payload.config.ts`; restart |
| A new field or global is not in the API even though the code is right | The running CMS does not pick up `payload.config.ts` or field changes | Restart `pnpm dev:cms` after any change to a collection's fields or to the config. Then `pnpm seed` |
| `pnpm seed` or `pnpm dev:cms` hangs on `Accept warnings and push schema to database? › (y/N)` | The SQLite file has a schema from another branch (you switched between `main` and `solution` in one clone) and `push` wants to drop columns | Answer `y`, or `pnpm reset`. Attendees never see this; keep `solution` in a second clone |
| `pnpm seed` fails with `DrizzleQueryError … SQLITE_ERROR: index … already exists` right after a schema change | The seed's own schema push raced the dev server's | Run `pnpm seed` again. Waiting a few seconds after the CMS restarts avoids it |
| `pnpm verify` says `GET /api/projects returned 0` while curl works | Node `fetch` dropped a keep-alive during a Next recompile | Verify retries 4 times; if it still fails, the CMS is mid-recompile: wait and rerun |
| Card C: `tsc` error `TS2769: No overload matches this call` at `payload.update` when seeding rich text | Hand-written Lexical JSON is not typed | Type the value as `Project['body']` (see the solution branch) |
| Card C: `pnpm --filter web add @payloadcms/richtext-lexical` warns `Issues with peer dependencies found` | Peer warning only | Harmless, carry on |
| `payload-types.ts` shows as modified before anyone ran `pnpm generate:types` | The dev server regenerates it on config change | Expected. Stage it with the step's commit |
| A `(card X)` commit is refused with "card X is not visible in the API" | The card's field exists but no project has it filled | Seed it or fill it in the admin, restart the CMS if the field is new |
| `getGlobal('profile')` does not typecheck | Types not regenerated after adding the global | `pnpm generate:types` |
| Relationship renders `[object Object]` or a number | Depth 0, or not handling `number \| Service` | `depth: 1` in the query; `typeof s === 'object'` guard |
| Rich text renders as JSON | Missing `convertLexicalToHTML` | Card C instructions |
| The commit hook refuses a `(step N)` commit | The step is red | That is the gate working. `pnpm verify N`, fix the ✘ |
| Someone removed the tag to get the commit through | Dodging the gate | Their `pnpm verify --status` stays red for that step. Ask them to amend the message once green: `git commit --amend` |
| Claude "fixes" it by editing `.claude/hooks`, `scripts/verify.mjs` or `.env` | Hooks will block; the diff should be refused | Teaching moment: read the diff |
| Claude writes a Postgres migration | It is following the generic Payload skill | Point at CLAUDE.md: SQLite + `push: true`, no migrations here |
| Someone accepts a 200-line diff unread | Solo work: nobody else is reading, and the habit slipped | Stop them. Ask them to summarise what changed. If they cannot, `git checkout .` and rerun the step in plan mode. |
| Someone is stuck on a word, not on the code | Jargon. "What is depth?", "what is a global?" | Point at `docs/GLOSSARY.md`; it is grouped and each word has the WP equivalent |
| `pnpm seed` prints nothing and creates nothing | `payload run` exits the moment the module finishes evaluating; the seed function was called without `await` | Top-level `await seed()` (see the comment in `seed.ts`). Claude often "fixes" this by wrapping in `.then()`, which does not help |
| Claude Code runs `pnpm dev` and Astro "exits" with a `Dev server running (pid …)` message | Astro 7 detects an AI-agent environment and daemonises the dev server | It is still running. `pnpm --filter web exec astro dev logs`, `… status`, `… stop`. In a human terminal it stays in the foreground |
| CMS boots but every page is a 500 with "Could not find the Next.js package" | `turbopack.root` in `next.config.ts` pointed below the monorepo root | Already fixed in the starter (`root: ../..`). Mention it if someone re-scaffolds |
| `EADDRINUSE :::3300` on `pnpm dev` right after a Ctrl+C | The `next-server` child outlived the pnpm wrapper | `lsof -nP -iTCP:3300 -sTCP:LISTEN` then `kill <pid>`. `pnpm doctor` catches it before you start |
| Port 3300 or 4321 in use | Previous `pnpm dev` still running | `pnpm doctor` names the process; stop it (Docker Desktop likes 3000, which is why the CMS is on 3300) |

## Debrief questions (3 min)

1. Which WordPress concept mapped most cleanly? Which did not map at all? (Expected: ACF → fields clean; options page → global clean; `the_content` filter / template hierarchy don't map; `depth` has no WP equivalent.)
2. Which diff did you reject, and why?
3. Which gate went red on you, and what did the ✘ line teach you?
4. What would you put in CLAUDE.md that was not there? (Capture answers. Fold them into claude-kit's payload stack.)

## After the session

- Collect every "what would you add to CLAUDE.md" answer and open a PR on `claude-kit`.
- Share the `solution` branch link and this repo.
- Take-home is step 7 in the brief: home page + deploy. Follow-up session: review the deployed portfolios and do deployment properly.
